# v0.9.0 – Household settings and categories

### Added
- **Settings in the card** (admins only): a gear in the header opens the household settings. Changes apply at once and reach every open board.
  - **Approval limit:** from which estimated price a purchase needs a second adult (was API-only).
  - **Categories:** the household's own categories with a colour, e.g. *Garden* or *Car*. Add, rename, recolour, delete; deleting clears the category on its tickets (recorded in their history) and series.
  - **Members:** role per Home Assistant user (replaces the trip to the developer tools) and whether they appear on the board. Hidden members do not show up as filters or for assignment.
- **Category on tickets:** one per ticket, set in the ticket dialog, shown in colour on the tile, filterable in the header. New tickets take the category selected in the filter. Recurring series pass it on to every round.
- The `create_ticket` action and the MCP tool `haushalttickets_create_ticket` accept a category by name; `haushalttickets_household` lists the categories; ticket summaries in events and MCP carry the category name.
- New event type `settings_changed` (categories, roles, visibility, approval limit).
- The emergency UI shows a ticket's category.

### Changed
- `PATCH /api/v1/users/{id}` takes `role` and/or `board_visible`.

### Upgrade
- **Ticket server:** `haushalttickets-update` – runs migration `0005` (categories, board visibility).
- **Home Assistant:** update the integration in the Marketplace, restart, then reload the browser and the app once so the new card loads.
- **Nightly run:** `haushalttickets-agent-update` (version number only).
- Update the server before the integration; the card works with an older server but shows no categories.
